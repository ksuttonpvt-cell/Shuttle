    Web address

    The address used in customer links, texts, emails and QR codes. Use your own, like shuttle.yourdealership.com.

    How to point your own address here
    1. Add the address to your domain in Cloudflare (or move the domain's DNS to Cloudflare).
    2. In Cloudflare: Zero Trust → Networks → Tunnels → this shuttle's tunnel → Public hostnames → Add. Enter the address and point it to http://localhost:3000 (the site's port).
    3. Come back here, type the address, tap Check, then Save. Staff sign in again on the new address.

    Email account

    Use a shared dealership mailbox (like shuttle@yourdealership.com) from your own email system, never a person's own email. The site won't accept an address that belongs to someone on staff.

    Setup help
    • Microsoft 365: server smtp.office365.com, port 587, the mailbox's address and password. Your IT admin may need to turn on “Authenticated SMTP” for that mailbox. If the account uses two-step sign-in, make an app password.

    • The password stays on the shuttle PC. It's never shown again or sent to anyone's browser.
    • If the dealership number is set up, people with a phone number on file get password links by text too.

    Page speed on real devices

    Loading…
    What each part means, and what helps
    • Finding the address (DNS): the phone asking where your site's address is. Slow here means the Wi-Fi or router's DNS. On the Ubiquiti router, set the DNS servers to 1.1.1.1 and 1.0.0.1, and make sure there's no local DNS record or host override for the site's address.
    • Connecting: reaching Cloudflare. Slow here means weak Wi-Fi or cell signal.
    • Waiting for the shuttle PC: Cloudflare passing the request to the PC and back. Slow here means the PC was asleep or busy, or the Cloudflare connection was reconnecting (see Shuttle Control).
    • Downloading / building the page: the phone itself. Older phones take longer.
    • Loading rides and data and Map images: after the page appears. Map images come from OpenStreetMap, not from your PC.
    • Only times are kept (for 14 days), with the page and kind of device. No names, tracking links or IP addresses.

    Connection speed

    Times how long this device takes to reach the shuttle server and back, through Cloudflare.
    If it feels slow or laggy
    • On the server PC, open Shuttle Control. The Cloudflare card should say Connected with 2–4 connections.
    • If the connection keeps dropping, set the Cloudflare connection type to HTTP/2 in Shuttle Control. Some routers' security features slow down QUIC (UDP).
    • On the Ubiquiti router, make sure Smart Queues limits are above your fiber speed (or off), and that IDS/IPS isn't blocking cloudflared.
    • Plug the server PC into the router with a cable instead of Wi-Fi, and set its Windows power plan so it never sleeps.
    • A heavy game server on the same PC can slow it down at busy times; the site itself needs very little.

    Updates & restart

    Loading…
    Recent changes installed

      Backups

      At midnight, in this order: the day's report is saved, customer info is cleared, then the nightly backup runs (so the report is in it). Nightly backups are kept 14 days. “Back up now” copies are removed at the next midnight clear, so they don't keep customer details.

      Remove all staff

      Removes every account except super admins: they're signed out everywhere and can't sign in again, and their emails can be used for new accounts. Their names stay on past rides, shifts and reports. Account requests waiting for approval are deleted. A backup is made first.

      Daily reports

      Saved every night at midnight for the day before: the shuttle's day (rides, people, on time, drive and wait times, shifts, GPS gaps) and the server's (requests, errors, response times, slowest requests, page speed on devices, the most common errors). No customer names, numbers or addresses.
